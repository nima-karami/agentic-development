# Compose the factory, build the spine

No open-source project, hosted product or published reference implementation covers the Software Factory PRD end to end, and none reaches the PRD's definition of done: a deployed artifact with every acceptance criterion mapped to runtime evidence, hard budget stops enforced outside the agent, and an append-only run record readable without the harness. The open field stops at a pull request or at orchestration of CLI agents. The closest projects are **Gas City** (MIT, v1.5.0, 1,424 stars), **OpenHands "Agent Canvas"** (MIT, v1.29.0, 91,497 stars, self-labelled beta), and **StrongDM Attractor**, which is a 5,700-line natural-language spec with no code. Each one misses the same core of the PRD: PRD approval (FR-5), budget ceilings (FR-57/NFR-3), a cost ledger (FR-35), per-attempt evidence bundles (FR-26), protected gate files (FR-14) and the release, deployed-QA and observe stages. Those missing pieces are the factory's spine: the conductor, the stage contracts and gates, and the run record. The lab has to build that spine, and it is small. Almost everything around it can be adopted as is: a budget-enforcing model gateway (LiteLLM or Bifrost), Playwright for runtime QA, a preview-deploy target (Vercel hosted, or Coolify self-hosted), ntfy for notifications, the Agent Skills format with its validator, and Harbor or Inspect for the portability spike. The main shortcut is that the spike's P0 requirements need **no durable workflow engine and no observability platform**. Resume after interruption (FR-17) is P1. The spike dashboard must match the run record (SA-8), so the simplest dashboard is generated from that record.

Gas City's own docs do call it "the platform for building software factories" ([docs overview](https://github.com/gastownhall/gascity/blob/main/docs/index.mdx)). Several other self-described factories surfaced but were only skimmed: **Orbi** (AGPL-3.0, issue to merged PR and tagged release), **SuperPlane** (8,120 stars, Apache-2.0 with an `/ee` directory, relevance unverified), **SWE-AF/CodeAF** (Apache-2.0) and **Archon** (MIT, 23,740 stars, "make AI coding deterministic"). None was run, so treat their fit as unverified ([Orbi](https://github.com/orbi-build/orbi), [SuperPlane](https://github.com/superplanehq/superplane), [SWE-AF](https://github.com/Agent-Field/SWE-AF), [Archon](https://github.com/coleam00/Archon)). Hosted agents (Copilot cloud agent, Codex cloud, Jules, Devin, Factory) also end at a PR and keep their logs inside the vendor UI. App builders (Replit, Lovable, Bolt, v0) do reach a deployed app, but they give the least control over gates and evidence ([GitHub Docs](https://docs.github.com/en/copilot/concepts/agents/coding-agent/about-coding-agent), [Altar.io](https://altar.io/ai-app-builders-founders-comparison-2026/)).

All of these candidates share four holes. None enforces a **budget ceiling** as a hard stop. None runs **QA against a deployed target** before a release gate. None records an **owner approval** as a first-class gate event. None stops the product loop from **editing its own gates** (FR-14). These are exactly the PRD requirements that trace to published failure classes: unbounded retry loops, phantom verification and runaway spend ([IAL-Scan summary](https://codex.danielvaughan.com/2026/07/06/infinite-agentic-loops-ial-scan-unbounded-feedback-codex-cli-rollout-budget-loop-defence/), [failure taxonomy](https://codex.danielvaughan.com/2026/06/03/coding-agent-failure-taxonomy-nist-style-classification-detection-codex-cli/)). On gate integrity the lab's handoff-block pipeline is already ahead of every open reference found. The thing to build is therefore the gatekeeping spine, not the agent runtime.

### Pipeline and outer graph: the engine is not the record

Durable engines handle retries, timeouts and human waits well. Temporal waits on a Signal, Hatchet's durable tasks pause on wait-for-event and resume without replaying approvals, DBOS uses `send`/`recv`, and Windmill suspends a flow until approval URLs are hit ([Temporal message passing](https://docs.temporal.io/develop/python/message-passing), [Hatchet durable execution](https://docs.hatchet.run/home/durable-execution), [DBOS communication](https://docs.dbos.dev/python/tutorials/workflow-communication), [Windmill approvals](https://www.windmill.dev/docs/flows/flow_approval)). None of the fetched documentation describes a **per-workflow cost or token ceiling**. Budgets would be application logic in every engine. Engine state also lives in framework-shaped Postgres tables, not the open, owner-controlled files that FR-16 and NFR-9 ask for. The only documented production pattern for mixing harnesses inside an engine is Duolingo's. Its `CodingAgent` library wraps Codex CLI and the Claude Code SDK behind a single enum, and each step is one retryable Temporal activity. The post describes **no human review gate and no state model** ([Duolingo](https://blog.duolingo.com/agentic-workflows)). The conclusion is that the factory writes its own run record whatever engine sits underneath. For the spike, a conductor that persists a transition to the JSONL log after every stage already satisfies FR-16, and FR-17 resume is P1. Adding Temporal (whose documented compose setup brings Postgres and Elasticsearch) before the spike would be over-production. At P1, Hatchet (MIT, Postgres required, RabbitMQ optional) and DBOS (MIT, a library plus Postgres) are the lightest options ([Hatchet self-hosting](https://docs.hatchet.run/self-hosting), [DBOS architecture](https://docs.dbos.dev/architecture), [Temporal deployment](https://docs.temporal.io/self-hosted-guide/deployment)).

### Harnesses and sandboxes: interchangeable parts, one archived trap

Harness independence (FR-52, NFR-8) is cheap because the field has converged on two portable seams. The first is ACP, which OpenHands uses to drive Claude Code, Codex, Gemini CLI, Pi, OpenCode or any stdio ACP server. The second is the SKILL.md format, which Codex, Gemini CLI and Claude Code all load ([OpenHands ACP](https://docs.openhands.dev/openhands/usage/agent-canvas/acp-agents), [Agent Skills spec](https://agentskills.io/specification), [Codex skills](https://developers.openai.com/codex/skills), [Gemini CLI skills](https://geminicli.com/docs/cli/skills/)). For sandboxes, **E2B is the only confirmed Apache-2.0 stack with a documented self-host path** (Terraform to AWS, GCP, Azure or Linux). Hosted Pro costs $150/month plus usage, with 24-hour sessions ([E2B](https://github.com/e2b-dev/E2B), [E2B pricing](https://e2b.dev/pricing)). Vercel Sandbox and Modal are managed-only. **Daytona's repository was archived on 2026-10-03**, and its owner's notice says core development moved to a private codebase. Harbor and Inspect still list Daytona as a sandbox without any warning ([Daytona](https://github.com/daytonaio/daytona)). For the P1 desktop archetype, GitHub-hosted runners provide Windows at $0.010/min and macOS at $0.062/min per job, with no 24-hour floor. Dedicated Mac hosts on AWS or Scaleway carry a **24-hour minimum** tied to Apple's license terms ([GitHub runner pricing](https://docs.github.com/en/billing/reference/actions-runner-pricing), [AWS EC2 Mac FAQ](https://aws.amazon.com/ec2/instance-types/mac/faqs/), [Scaleway](https://scaleway.com/en/pricing/apple-silicon)). A 24-hour session cap on every hosted sandbox means long unattended runs need to resume from snapshots plus repo state, which pushes FR-17 into the design early even though it is P1.

### Deploy and QA: the platform's "succeeded" is not a gate

Vercel emits `deployment.succeeded` with a `target` field distinguishing preview from production, and its Checks API attaches pass/fail results to a deployment. Coolify (Apache-2.0) runs PR previews on their own domains and cleans them up automatically ([Vercel webhooks](https://docs.vercel.com/docs/webhooks), [Vercel checks](https://vercel.com/docs/observability/checks-overview/creating-checks), [Coolify previews](https://coolify.io/docs/applications/deployments/preview-deployments)). Neither event amounts to SA-1's "renders the app", so the factory still needs its own HTTP probe and browser pass. For evidence, Playwright MCP captures screenshots and, with `--caps=devtools`, traces and video. agent-browser records webm/mp4 and diffs screenshots against a baseline. Microsoft's own README recommends **Playwright CLI with skills over MCP for coding agents** on token cost ([Playwright MCP](https://github.com/microsoft/playwright-mcp), [agent-browser](https://github.com/vercel-labs/agent-browser)). The reproducible pattern is to let an exploratory driver find the path, then persist a deterministic Playwright script and its trace as the FR-13 evidence item. One open risk sits squarely in the spike's path: Vercel deployment protection blocks unauthenticated browser QA, and the bypass-token mechanics were not verified.

### Run record, gateway, notifications: borrow transport, own the schema

Claude Code ships the richest first-party telemetry. It emits `claude_code.cost.usage` and `token.usage` by model, plus `api_request` events with `cost_usd` and request IDs. With `OTEL_LOG_RAW_API_BODIES=file:<dir>` it writes untruncated bodies to disk, which is a ready transcript source for FR-26 evidence bundles ([Claude Code monitoring](https://code.claude.com/docs/en/monitoring-usage)). Codex CLI and the OpenHands SDK also export OTLP, but their schemas differ, and the OTel GenAI conventions remain "Development" with no tagged release as of August 2026 ([Dash0](https://www.dash0.com/knowledge/opentelemetry-genai-semantic-conventions-explained), [OpenHands observability](https://docs.openhands.dev/sdk/guides/observability)). No observability platform models item → stage → attempt (FR-27). Three have changed hands in 2026: Langfuse, Helicone (now in maintenance mode) and Traceloop ([OpenObserve](https://openobserve.ai/blog/langfuse-alternatives.md), [PostHog](https://posthog.com/blog/best-helicone-alternatives), [Traceloop](https://traceloop.com/blog/traceloop-is-joining-servicenow)). So the factory owns the schema: JSONL events, evidence files and FTS. Langfuse or Opik can come in later as a replaceable view fed by OTLP. The **hard stop belongs at the gateway**, not in harness telemetry, which is self-reported. LiteLLM rejects over-budget requests per virtual key, per model and globally. Its docs warn that the global budget **fails open without a database**, and that for team-owned keys only team budgets are enforced ([LiteLLM budgets](https://docs.litellm.ai/docs/proxy/users)). Minting one key per stage attempt therefore gives NFR-3 enforcement and per-stage cost (SA-5) in a single mechanism. Notifications are the thinnest layer researched: ntfy is a small self-hostable Go binary that any orchestrator can hit with one curl ([Railway template](https://railway.com/deploy/ntfy-server)). The FR-32 fields, FR-33 dedupe and NFR-10 redaction are factory code either way.

### Evals and skills: runners exist, the guardrails don't

Harbor is purpose-built for FR-56. Its tasks are directories (`instruction.md`, `task.toml`, `environment/`, `tests/test.sh` writing a reward). It ships 42 pre-integrated agents, including claude-code, codex, opencode, goose and openhands, and its job config pairs each agent entry with its own `model_name`. Trajectories in ATIF carry `final_metrics` with tokens and cost ([Harbor tasks](https://docs.harborframework.com/tasks/overview.md), [agents](https://docs.harborframework.com/agents/pre-integrated-agents.md), [ATIF](https://docs.harborframework.com/agents/atif.md)). Inspect AI with inspect_swe is the MIT alternative. It has stronger logging, but it does not describe cost reporting ([Inspect eval logs](https://inspect.aisi.org.uk/eval-logs.html), [inspect_swe](https://meridianlabs-ai.github.io/inspect_swe/)). `claude plugin eval` offers the most CI-ready gate semantics: a with/without baseline arm, pinned `--model`, `--max-cost-usd` and exit codes 0/1/2. It is limited to Claude Code and Claude models, so it can gate skill edits but cannot satisfy FR-56 ([plugin evals](https://code.claude.com/docs/en/plugin-evals.md)). For self-improvement, the evidence favours constrained optimisation over open self-modification. GEPA (MIT) optimises any text against a numeric evaluator with a train/val split, but its docs describe **no safeguard against a gamed evaluator** ([GEPA docs](https://gepa-ai.github.io/gepa/)). SkillsBench found self-generated skills negligible or negative, per a search summary ([arXiv 2602.12670](https://arxiv.org/pdf/2602.12670)). Press reports say the Darwin Gödel Machine faked logs to pass its own checks, though this was not confirmed in primary wording ([The Register](https://www.theregister.com/2025/06/02/self_improving_ai_cheat/)). That makes FR-14 (gate and eval files writable only by the factory loop) the load-bearing control for the whole self-improvement loop, not a nicety. On the skills side, the Agent Skills spec has **no versioning, registry or overlay mechanism** beyond a free-form `metadata` map ([spec](https://agentskills.io/specification)). `npx skills` documents no lockfile ([vercel-labs/skills](https://github.com/vercel-labs/skills)). FR-40 pinning and the FR-42 drift diff are therefore a hash-and-diff script the lab owns. Spec Kit (142,310 stars), OpenSpec and cc-sdd all emit prose Markdown with no schema validation, and they overlap heavily with the lab's feature-spec and implementation-plan seeds. Adopting any of them wholesale would duplicate stages ([Spec Kit](https://github.com/github/spec-kit), [OpenSpec](https://github.com/Fission-AI/OpenSpec), [cc-sdd](https://github.com/gotalab/cc-sdd)).

## Seven adopted tools plus a thin spine pass the spike

PRD section 8 scopes the spike to one web-app intent on the happy path, with SA-1 through SA-11 verified by a second agent. The smallest composition that covers it is below. The guiding rule is that a P0 requirement which can be met by writing a file needs no extra infrastructure.

|---|---|---|

What remains to build is narrow, and it is the part that separates this factory from the open field. The conductor sequences stages and never judges its own output. Stage contracts wrap the existing seed skills' handoff blocks. Exit codes are captured directly rather than parsed from prose. The run record and its generated dashboard, the gate-file protection, the PRD validator and approval recording, budget wiring through gateway keys, and the notification template complete the list. Everything with real engineering depth (agent runtimes, browser automation, sandbox isolation, deploy pipelines, gateway accounting, eval matrices) is adopted. The P1 additions follow the same shape. A durable engine (Hatchet or DBOS) arrives when FR-17 resume lands. Langfuse or Opik can arrive if a trace UI earns its keep. OpenHands Agent Server is an option once concurrent isolated items (FR-20) matter. GitHub-hosted runners cover the desktop archetype.

## Conclusion

The market has commoditised the agent: a dozen runtimes, sandboxes and browser drivers are interchangeable behind ACP, SKILL.md and OTLP. Trust has not been commoditised. Not one candidate refuses to advance on an agent's say-so, caps spend outside the agent, keeps an evidence record that outlives its harness, or locks the product loop out of its own gates. The factory's defensible core is therefore its gatekeeping and record-keeping layer, and the lab's existing handoff-block discipline is already ahead of every open reference on exactly that axis. Working smart means building that layer thin and refusing to build anything else.

The second implication is about sequencing. PRD priorities sort cleanly into "write a file" (P0) and "run infrastructure" (P1). The spike can prove all eleven acceptance criteria with a JSONL log, a gateway, Playwright, a preview host and ntfy. That keeps the expensive and contested choices (durable engine, trace platform, sandbox vendor at scale) open until the run record shows what they actually need to carry. The self-improvement loop is the one place where an adopted tool is actively dangerous without a guard. GEPA-style optimisers trust their evaluator, and published self-modifying systems were reported gaming theirs, so FR-14 is the precondition for turning that loop on at all.
