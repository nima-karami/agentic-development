6 · Three postures

Incumbents, the agent-first fringe, and open source

Incumbents and open source kept the human. Two companies dropped it.

Established companies

  • Human sign-off stays; AI review sits in front of it.
  • The stated worry is governance: 84% of leaders say the hardest part is what happens to AI code after it's written.
  • After a March 2026 incident wave (about 120,000 lost orders) , Amazon required senior sign-off on AI-assisted changes from junior and mid-level engineers.

Agent-first fringe

"Code must not be reviewed by humans." StrongDM engineering charter, confirmed via Simon Willison. The claim that OpenAI's Harness team made human review optional couldn't be confirmed from the primary source.
  • Deterministic gates, held-out tests and a second model replace human reading.
  • Two named companies. Not a trend yet.

Open source

  • AI may assist. A human is the author, signs the CLA, and must be able to explain the code.
  • Kubernetes closes PRs when an agent answers review comments. CPython forbids altering or bypassing tests to get a pass.
  • Across 1,000 repos, 118 had an AI policy and 74% of those require a human in the loop. In one developer's sample of 30 projects, 19 had a rule and 14 of those appeared in 2026.

10 · The playbook

How to review agent-written code and codebases

Sort each change by risk, put it through eight steps, and audit the codebase when drift shows up.

Built from what at least two of the three reports agree on and the verified numbers support.

First, classify the change. Everything after keys off this.

Risk classWhat falls in itReview depth
GateCI config, test harness, lint rules, coverage thresholds, agent instruction files. Anything that changes how future work is judged.Highest. A human reads every line, every time. Flagged automatically by path.
HighAuth, permissions, money, persistence and migrations, deploy and infrastructure, public API contracts.A human reads every line, plus runtime proof.
NormalFeatures and fixes inside existing boundaries.Human reads boundaries and tests, samples the rest, trusts green gates for the body.
MechanicalRenames, formatting, generated code, dependency bumps with passing suites.Gates and an AI reviewer. A human only confirms scope.

The codebase audit runs on triggers

Run it when a signal crosses its threshold, or quarterly without telemetry. The output is a task list.

Triggers

  • Duplication percentage rising for two measurements in a row
  • Code rewritten within two weeks climbing
  • Incidents or reverts per merged PR climbing
  • Any unreviewed merge in the Gate or High classes
  • Gate warning counts growing, or a gate quietly switched to advisory

What the audit checks

  • Duplicate and near-duplicate helpers, by name and by shape
  • Error masking: swallowed exceptions, defaulted failures, broad catches
  • Test strength on a sample: mutate the code, count tests that still pass
  • Architecture invariants: dependency direction and existing module boundaries
  • Gate rot: anything disabled, narrowed or made advisory since the last audit
  • Dead code and orphaned files from abandoned agent attempts

Measure five things

MetricWhy
PR size at P75, by author typeSize predicts findings and review cost, and agent PRs run large.
Time to first review and time in reviewThe first numbers to move when reviewers start avoiding agent PRs.
Unreviewed merge rate, by risk classMust be zero for Gate and High.
Revert and incident rate per merged PRThe escape rate, and the only outcome measure here.

Watch for the largest PRs getting the shortest reviews. In the benchmark data that pattern comes before the incident spike.

Rules that hold at any team size

  • No agent edits, narrows or skips a test to get green. A gamed gate is a failed task.
  • Self-review by the authoring agent isn't review.
  • The AI reviewer informs. A human owns the merge.
  • Verify by re-running the command and checking its exit code.
  • Disclose AI involvement. A named person is accountable for every merge.
  • Split big changes before building.

Skip until the evidence improves

  • A hard line-count cap. The 400-line figure is old. Use the risk class and "one named check" instead.
  • Several AI reviewers voting. Their blind spots overlap; one independent reviewer plus a human has the evidence.
  • Dropping the human. Two companies have, both with held-out tests and heavy instrumentation.
  • Governance dashboards and policy engines, unless you sell to regulated buyers.
  • A fixed audit calendar as the only trigger.
